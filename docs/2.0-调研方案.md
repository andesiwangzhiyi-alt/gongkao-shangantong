### 0.2 当前数据结构（每题）

```js
{ id:"gk00001", type:"真题", stem:"…", options:[…], answer:0, analysis:"【正确率 36%｜考点：重要文件】…",
  tag:"重要文件", multi:false, mat:"…", mat_images:[…], images:[…], opt_images:[…], rate:36, num:1 }
```

**核心缺口：没有 `src`（省份）/`year`（年份）/`paper`（卷种 A/B/C、地市/副省/执法）/`no`（卷内题号）字段。**
当前来源识别靠 `qSource()` 从 id 前缀和 tag 粗判（国考/省考/模考），无法满足"每道题知道来自哪个省哪一年哪套卷"。

### 0.3 已确认的硬问题（按严重度）

1. **questions6.js 单文件 235MB** —— 浏览器需下载+解析 235MB 单 JS，首屏极慢、内存峰值高、GitHub Pages 加载体验差。**2.0 必须拆分/懒加载**。
2. **省考真题 8,489 题缺材料**（text 版遗留），资料分析不可作答；且省考 raw 文件已不在 Downloads，无法直接重加工。
3. **PAPER_CONFIGS 卷种结构与真实卷脱节**。实测 2025 江苏 A 卷（粉笔网友回忆版 PDF，28 页 135 题）：
   `政治9 + 常识11 + 言语25 + 数量18 + 判断49 + 资料23`，而现行模板是 `常识15+言语45+数量20+判断45+资料10`，**每个模块都对不上**。
4. 个人数据只有模块级汇总（byMod answered/correct），**无法做考点级/难度级/来源级能力分析**，错题本只有 count/mastered。
5. 导出 PDF 目前是自定义版式（`printPaper`），非真题卷样式；题干前无来源注明；无答题卡页；无"纸质做完回填"通路。

## 1. 方向一：组卷能力全面升级（2.0 核心）

### 1.1 数据基建：来源元数据精细化（一切的前提）

**目标**：每道题带 `src:{province, year, paper, type, no}`，支持"这个省/这年/这套卷/第几题"的精确溯源与筛选。

**可行路径**（raw 文件 804 份在，`paper.name` 是金矿）：
- `fb_国考_*.json` 的 `paper.name` 示例：`2021年国家公务员录用考试《行测》题（地市级网友回忆版）` → 解析出 `{province:'国考', year:2021, paper:'地市级'}`
- `fb_国考模拟题_/fb_省考模拟题_*.json` 的 name 示例（模考）：`2026国考模考大赛第10季` 或 `2025省考模考（山东卷）` → `{province, year, paper:'模考·第N季'}`
- 解析规则写成一个独立模块 `parse_paper_name.js/py`（规则表驱动，覆盖：国考副省/地市/执法、各省 A/B/C 类、行政执法卷、网友回忆版、联考、模考 N 季、冲刺卷…），**未命中规则时降级为"未知来源-需人工补标"并输出清单**，不静默丢弃。
- 每个 item 的 HTML 里已有 `title-index`（卷内题号）→ 直接落 `no` 字段；`title-type-name`（单选题/多选题/不定项/判断题）→ 落 `qtype`（真题 vs 模考）。

**省考真题缺口处理（二选一，建议 A）**：
- **A. 重爬省考真题**（推荐）：沿用 crawler_v2.js，SCOPE='省考'，一次补齐"完整 HTML + 材料 + 来源元数据"，同时解决 8,489 题缺材料的历史问题。预计 98+ 套，按「40套+暂停5min」节流约 1-2 天挂机。
- **B. 找回旧 raw 文件**：若用户在备份盘/微信文件里有旧 `fb_省考_*.json`（text 版），可解析出 paper.name 补元数据，但材料缺失无法修复，不推荐作为唯一方案。

**题库存储格式 v2**（建议新增 `questions8.js` 或重构分片，见 1.4 性能方案）：

### 1.3 组卷引擎 v2（自由度是灵魂）

**需求拆解**：从"碎片练习 3-5 题"到"完整 135 题模考卷"全谱系组卷，筛选维度 = 省份×年份×卷种×模块×题型×考点×难度×来源×题量。

**推荐交互设计**（两个入口，覆盖全部场景）：
1. **快捷组卷**（碎片场景，首页卡片直达）：4 个滑杆/选择器 —— 题量（3~135）、模块（全选/单选）、难度（简单/中等/较难/困难/不限）、来源（全部/仅真题/仅模考/指定省份）。一键出题，默认去重（30 天内做过的题优先不重复）。
2. **卷种定制组卷**（完整场景，保留现有入口升级）：卷种模板 → 各模块题量可改（保留）→ **新增维度**：省份/年份范围/难度分布/题型（如只要图形推理 15 题）/考点白名单黑名单 → 出题策略（随机 / 按正确率配比 / 错题优先 / 考点均衡）→ 在线答 or 导出 PDF。

**出题策略（智能配额）**：完整卷按卷种结构分配题量后，每个模块内部按"考点均衡 + 难度正态 + 来源去重"采样：
- 考点均衡：模块内考点分布按全库该模块考点比例近似（避免整卷都是同一个考点）；
- 难度正态：按目标卷真实难度配比（如 40% 中等 + 30% 简单 + 20% 较难 + 10% 困难）；
- 来源去重：同卷不出现同一真题卷相邻题连排、不出现重复题干。

**题库规模校验**：107,483 题、省考+国考真题 12,722 题、政治理论模块现有题量（需统计）——组卷页显示每个维度组合的可用题量，**题量不足时降级提示**（如"仅真题+资料分析：可选 1,234 题，最多组 8 题"），绝不静默少题。

### 1.4 导出格式 v2（对标粉笔真题卷，用户指定参考物）

**参考基准已实测**：《2025年江苏省公务员录用考试《行测》题（A类）（网友回忆版）.pdf》（Downloads），其版式特征：
- 每页页眉：卷全名（`2025年江苏省公务员录用考试《行测》题（A类）（网友回忆版）`）
- 每页页脚：`· 本试卷由粉笔用户XXX生成` + `第 N 页，共 M 页`
- 分节标题带**答题指令**：`一. 政治理论：根据题目要求，从四个选项中选出一项最恰当的答案。`（六节各有指令文案）
- 题目连续编号 1~135，题干文字排版紧凑，选项 A./B./C./D.
- 资料分析材料与小题同页处理，材料先行
- 试卷本身不含答案解析（答案解析另册/在线）

**上岸通导出 PDF v2 设计**（新版式，建议整体替换 v1.14 的 printPaper）：

1. **卷头**：`202X年XX省公务员录用考试《行政职业能力测验》题（XX类）` + 副标题行（上岸通智能组卷 · 作答时限 XX 分钟 · 满分 100 分）+ 组卷日期；卷头下「注意事项」框（沿用真题话术）。
2. **分节**：按模板 parts 输出，节标题 = `一. 政治理论：根据题目要求，从四个选项中选出一项最恰当的答案。`（每节指令文案按真题实际文案建表）。
3. **逐题来源注明**（用户明确要求）——每题题干前一行小字：
   `【来源：2021 国考·地市级·第 23 题 · 正确率 63% · 考点：行政管理】`
   真题卷导出时默认显示来源；若用户选"模拟全真"开关可隐藏（真考试代入感）。
4. **材料处理**：资料分析/言语片段材料框（虚线框），统计表图以「（见图 N）」占位 + 图 URL 列表附页，或直接嵌入图片（有本地图时）。**建议 v2 默认直接嵌入图片**（离线打印可用，图已本地化 5,611 张）。
5. **答题卡页**（真题卷体验关键）：A4 横向/纵向答题卡样式——题号 1-135 填涂格（5 题一行），页脚考试提示。可选手写答案区。
6. **答案解析册**（独立分册，`page-break-before` 另起）：`参考答案与解析`——每题：答案 + 正确率 + 考点 + 完整解析。**真题卷"试卷+答案分册"结构**。
7. **回填二维码**（对应"做完答案回填线上"）：卷头或封底印二维码（URL 带 `?paper=xxx` 一次性卷 ID），扫码/点开进入回填页；回填页按题号矩阵输入答案 → 自动判卷 → 写入个人记录（与在线做题同一套 recordResult 链路，见方向二）。**离线打印→扫码回填→数据入库**闭环。

**导出实现建议**：沿用 `window.open + print → 另存 PDF`（零依赖，移动端/桌面都可用）；页眉页脚用 `@page` margin-box 或每页重复 `position:fixed` 元素（浏览器打印支持度需在 Chrome/Edge 实测，列为验证项）。**重要**：打印页需要 `-webkit-print-color-adjust: exact` 保证底色/边框打印不丢。

### 1.5 组卷与数据打通

组卷出的卷子自动带 `paperId`（localStorage 记录），整卷作答自动进个人数据（对错/用时/正确率），错题自动进错题本——**"做题-记录-分析-再组卷"闭环**。

## 2. 方向二：个人数据多维评析（2.0 另一半核心）

### 2.1 数据层升级：逐题作答日志

现状 `store` 只有聚合值。**新增 `store.attempts`（环形队列，上限 50,000 条，超出滚动淘汰）**：

```js
{ qid, ts:1690000000000, correct:true, picked:2, timeMs:38000,
  ctx:{kind:"daily"|"exam"|"custom"|"search"|"wrong", paperId?:"…"},
  mod:"判断推理", src:{province:"国考",year:2021,paper:"地市级",no:23},
  tag:"图形推理", rate:63, multi:false }
```

写入点：`recordResult()` 一处（所有答题入口都汇聚到这里，天然全覆盖）。迁移：旧 wrongs/stats 保留兼容，新数据以 attempts 为准。

### 2.2 能力画像（多维评析）

从 attempts 派生以下视图（纯前端计算，localStorage 即可，无需后端）：

1. **模块×考点矩阵**：每模块下按考点统计 做题数/正确率，热点图展示（红=薄弱，绿=扎实）。
2. **难度适配度**：各难度档（简单/中等/较难/困难）正确率 vs 全站平均（即 `rate` 分档）对比——"你在较难题上是否比平均更差"→ 定位是"基础不稳"还是"拔高不足"。
3. **来源适应度**：国考/省考/模考、不同省份真题的正确率差异（如：模考 55% vs 国考真题 68% → 真题适应力强）。
4. **趋势与稳定性**：近 14/30 天每日正确率折线 + 波动（标准差）；模块掌握度曲线（艾宾浩斯复习达标率）。
5. **用时画像**：模块平均用时 vs 目标用时（如资料分析每题 90s），识别"慢而准/快而错"。
6. **薄弱清单**：综合评分 `薄弱分 = 错误率×频次×近因权重`，输出 Top 10 薄弱考点，每条附：正确率、最近 7 天趋势、推荐动作（练 N 题）。

**推荐落地视图**：`更多 → 能力分析` 页（雷达图 6 模块 + 矩阵热点图 + 薄弱清单）；首页仪表盘加"今日薄弱提醒"卡片。

### 2.3 智能组卷个性化（方向一×方向二交汇）

`smartQuiz()` v2：
- 输入：薄弱考点 Top5 + 难度适配缺口 + 最近 30 天做过的题（去重）；
- 输出：15-20 题"补弱卷"（薄弱考点占 60%，难度按"当前档+1"拔高）；
- 一键生成"错题重做卷"（错题本中 count≥2 或近 7 天错的优先）。

### 2.4 数据安全

- attempts 达上限自动压缩（只留 汇总统计，弃明细）；
- 导出/导入 JSON 备份格式升级为 v2（含 attempts），**旧备份导入需做版本兼容**（检测无 attempts 字段则只恢复旧字段）；
- 可选：每日自动备份到 localStorage 冗余键 + 提醒导出。

## 3. 方向三：申论 AI 应用探究（3.0 前瞻，本轮只出调研）

### 3.1 四个子方向可行性评估

| 子方向 | 价值 | 技术可行性 | 成本 | 建议 |
|---|---|---|---|---|
| A. 做题时 AI 提示（不会做给 hint） | 高 | 高（选择题语境短，普通模型即可） | 低-中 | ✅ 2.0 末期可 POC |
| B. 看不懂解析 AI 讲解（把长解析转白话/追问） | 高 | 高（RAG 式：题目+解析+用户提问 → LLM 重讲） | 低-中 | ✅ 2.0 末期可 POC |
| C. AI 出新题（按考点/难度生成行测题） | 中-高 | 中（生成易，**质量/无重复/无错题校验难**，需人工抽检） | 中 | ⚠️ 3.0 实装，先做"AI 出题实验室" |
| D. 申论 AI 批改（要点匹配/结构/语言评分） | 高 | 中-高（长文评分需强模型 + 评分 rubric 工程化） | 高 | ⚠️ 3.0 实装，先 POC |

### 3.2 关键调研结论与建议

1. **模型通道已就绪**：用户已有中转站（worldcodes wc-sonnet/wc-opus、testvideo GPT 号池）与腾讯云服务器（可部署开源模型）。行测选择题提示/讲解用 wc-sonnet 级别足够；申论批改用 wc-opus 或云端部署 Qwen2.5-72B。
2. **交互形态**：纯前端 App 调 API 有 **CORS/密钥暴露** 问题——建议：本地起 `ai_proxy.py`（或腾讯云部署一个反向代理服务），App 只与自己的代理通信，密钥留在服务端；后续可平滑接入"按量计费 + 用量看板"。
3. **申论批改 POC 设计**（3.0 前做最小验证）：
   - 输入：题目（题干+材料）+ 用户答案 + 参考要点（素材库可先行提供要点模板）；
   - 输出：总分 + 分档（要点齐全度/结构/语言/卷面）+ 逐要点命中/缺失 + 提升建议；
   - 验证指标：与人工评分（用户自评或对照参考范文）的相关系数 ≥ 0.7 才算可用。
4. **AI 出题 POC**：以「考点标签 → 题目模板 → LLM 生成 → 自动校验（选项唯一性/答案与解析一致性/查重）→ 人工抽检入库」流水线评估质量；**AI 题必须标记 `src.kind:'AI'`**，与真题严格区分（用户重视来源真实性）。
5. **合规提醒**：粉笔解析版权归粉笔，AI 讲解基于题目重述/讲解属合理学习用途，但**不得把粉笔解析原文喂给外部 API 做二次分发**；AI 生成的"仿真题"不得宣称真题来源。

### 3.3 前置工作（本轮可做）

- `docs/申论-ai-调研.md`：收集申论评分维度（各省阅卷标准差异）、主流 AI 批改产品调研（粉笔 AI 批改、中公、华图、通用 LLM 对比）；
- 设计 `ai_proxy.py` 接口草案（/explain、/hint、/grade、/generate 四端点）；
- 成本测算：每次讲解 ~1-2K token 输入 + 300 输出；每月 1000 次讲解 ≈ wc-sonnet 用量可控；申论批改单篇 ~8K token 输入，需量入为出。

## 4. 方向四：UI 与交互优化

### 4.1 性能修复（先行，影响所有体验）

| 问题 | 方案 |
|---|---|
| questions6.js 235MB 单文件 | ① 按来源拆分（国考模考/省考模考）+ **按需懒加载**（进入模考页/组卷时才 fetch 对应分片，`<script>` 动态注入或 fetch+eval）；② 题库进 **IndexedDB**，首次加载后离线秒开；③ 首屏只载 questions.js~5（约 25MB），6/7 懒加载 |

### 4.2 交互问题排查清单（2.0 逐一验证）

- [ ] 7 个底部 tab 在窄屏（iPhone SE 375px）是否拥挤 → 方案：tab 压缩为 5 个（合并"每日一练"进首页、"申论"进更多），或 tab 文字缩写+图标化
- [ ] 答题弹层（quiz-layer）在长题干+图片题下是否可滚动、选项点击热区是否够大（≥44px）
- [ ] 组卷页在桌面宽屏是否充分利用（现在偏手机布局）→ 响应式断点补桌面两栏
- [ ] 键盘：答题 1-4 选 + Enter 提交已有；补 ←/→ 切题、M 标记
- [ ] 长题库检索（107K 题）doSearch 是否卡顿 → 结果防抖 + 虚拟列表（只渲染前 50）
- [ ] 打印页（导出 PDF 前）字体/分页在 Chrome 与 Edge 一致性
- [ ] 深色模式缺失（夜间刷题需求）→ CSS 变量化后一键切换
- [ ] 首屏 7 张截图（docs/screenshots）与当前 UI 是否脱节 → 更新文档

### 4.3 视觉动效升级方向（保持克制，紧扣核心功能）

- **基础**：CSS 变量统一色板（主色 #1c3f60 深蓝 + 金 #e8b64c 保留），间距/圆角/阴影 token 化；
- **答题反馈**：答对/答错的全屏轻动效（微光扫过 + 选项变色 + 轻微 scale），结果页正确率数字滚动动画（countUp）；
- **导航**：tab 切换内容淡入上移（150ms cubic-bezier）；底部指示条已有点缀，加"活跃 tab 图标微弹"；
- **卡片**：首页模块卡片 hover/active 微上浮 + 阴影加深；错题本/统计用骨架屏占位；
- **组卷流程**：卷种选择 → 题量确认 → 生成中（loading 态 300ms 以上给"试卷生成中…"动效）→ 完成，四步进度指示；
- **申论素材**：卡片流式布局 + 分类筛选 chip 动效；
- **克制原则**：动效全部 `prefers-reduced-motion` 降级；总 CSS 动画数控制在 30 个以内，不引入外部动画库（保持零依赖）。
