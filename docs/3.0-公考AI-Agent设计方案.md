# 上岸通 3.0 · 公考 AI Agent 设计方案

> 版本：v0.2（含实现细节） · 日期：2026-08-18
> 目标：构建一个**专精公务员考试**的智能体（Agent），支持——智能提示、深度解答、类题/新题生成、整卷模拟题生成、申论批改，以及基于个人画像的个性化辅导；**可独立使用**（CLI/HTTP/网页），也能嵌入上岸通 2.x。
> 前置调研：`docs/申论AI探究与3.0接口草案.md`（AI 能力边界与伦理）、`docs/ai_proxy_contract.yaml`（OpenAPI 契约 v0.1）、`docs/2.1-问题诊断报告.md`（2.x 待修问题）

---

## 1. 定位与设计原则

### 1.1 一句话定位

> 一个**懂公考、懂你、懂题库**的 AI 助教：能讲清每道题，能按考点出题，能批改申论，能根据你的错题画像给定制练习——而且能脱离上岸通单独跑起来。

### 1.2 设计原则

| 原则 | 说明 |
|---|---|
| **RAG 优先，模型次之** | 能检索题库/素材/大纲作答的，先检索再让模型组织；不把 15 万题塞进 prompt |
| **工具调用（function calling）** | Agent 有 6-8 个工具：检索题目、取题目详情、查考点分布、查大纲、组卷、批改申论等 |
| **分级提示，不泄答案** | 提示按"考点→思路→关键一步→答案"四级递进，默认不直接给答案 |
| **可独立、可嵌入** | 同一核心引擎以 Python 包 + HTTP 服务 + CLI 三种形态提供；上岸通 3.0 通过 `/api/ai` 调用 |
| **多模型供应商抽象** | 走 OpenAI 兼容协议，支持 ark（DeepSeek/GLM）、worldcodes、testvideo GPT 池等；Key 只存服务端/用户本地，不进前端 |
| **先校准，再上线** | 申论批改不冒充官方分数；所有 AI 内容标注"AI 生成，仅供参考" |

## 3. 知识底座（Agent 的地基）

### 3.1 题库索引

- 数据源：上岸通 `js/questions*.js` + `js/bank/questions6_*.js`（154,178 题，含 `src`/`num`/`tag`/`analysis`/`rate` 正确率）
- 形态：构建时转为 **SQLite（推荐）或 JSON 索引**，供工具快速检索
  - 表 `questions(id, mod, type, stem, options, answer, analysis, tag, src_name, src_year, src_exam, src_province, num, rate, point)`
  - 表 `materials(question_id, mat, mat_images)`（41,950 题带材料）
- 检索接口：
  - 关键词全文检索（stem/options/analysis）
  - 考点检索（point 字段）
  - 模块+难度（rate 分档）+来源过滤
- 关键点：**不用把题目原文放进 prompt**，Agent 用工具按需取 1-3 题；只有生成类题/新题时才把 1 道母题 + 考点定义传给模型。

### 3.2 考试大纲与测评要素

- 行测：政治理论/常识/言语/数量/判断/资料六模块的**测查要素**（官方考试大纲文字）
- 申论：阅读理解能力、综合分析能力、提出和解决问题能力、文字表达能力（+ 执法类：依法办事能力等）
- 卷种结构：`PAPER_CONFIGS`（11 种国省考卷种模板）+ 各省题量/时限
- 存储：`data/outline.json` + `data/paper_configs.json`（从 app.js 抽取固化）

### 3.3 申论素材库

- 现有 `js/shenlun.js` 21 条（金句/热点/案例/框架/模板）
- 扩充方向：真题范文（网友回忆版）、评分标准说明、高频热点
- Agent 出申论题/批改时，引用素材库避免泛泛而谈

## 4. 六大能力模块

### 4.1 智能提示（Hint）—— 分级递进，默认不泄答案

```
输入：题目（或题 id） + 用户请求"提示"
输出：最多 3 级提示 + 是否想看答案的引导

级别1（考点提示）："本题考查【数量关系-工程问题】的核心是"效率×时间=总量"，先想清楚谁是谁的效率。"
级别2（思路提示）："设总量为甲乙效率的最小公倍数（如 60），分别求甲乙效率，再求合作。"
级别3（关键一步）："注意甲先做 2 小时——先扣掉这部分工作量，再算剩余部分合作时间。"
答案按钮：用户明确请求后才给完整解析。
```

Prompt 模板（核心思想）：
```
你是公务员行测讲解老师。给出一道题，要求：
1. 先判断考点，给出【级别1】提示（考点名称+一句话破题方向），禁止直接说答案。
2. 若用户要求进一步，给出【级别2】（思路步骤），禁止算出最终数字。
3. 若用户要求再进一步，给出【级别3】（关键一步/易错点），仍不直接报答案。
4. 只有用户明确说"给答案/解析"时才输出完整解析（原解析 + 你的讲解）。
输出用中文，步骤编号，结尾加"🚫 提示≠答案，建议先自己算"。
```

### 4.2 深度解答（Tutor）—— 讲透 + 可追问

- 输入：题目 + 用户的选择（或"直接讲"）
- 流程：
  1. 工具取题目详情（题干/选项/答案/原解析/考点/正确率）
  2. 判断对错；答错时先共情再讲
  3. 输出：考点 → 思路 → 逐步推导 → 每个选项为什么对/错 → 易错点 → 同类题建议
- 追问支持："为什么 B 不对？""换个解法？"（有会话上下文）
- **关键**：多选/不定项要逐选项核对；资料分析题先展示材料再讲定位。

### 4.3 类题推荐 + 新题生成（Gen）

两种模式：

**A. 类题推荐（从题库找相似题）**
- 输入：1 道母题（题 id 或题干）
- 逻辑：按 `point`（考点）相同 → `rate` 相近 → 模块相同 → 关键词相似度排序，取 3-5 题
- 纯检索，零模型成本，秒出

**B. 新题生成（模型创作）**
- 输入：母题（可选）+ 考点 + 难度档 + 题量
- Prompt 约束：
  - 严格保持选项 4 个（不定项除外）、单选答案唯一
  - 考点与母题一致但数值/情境/人名换新
  - 输出必须是合法 JSON：`{mod, stem, options[4], answer, analysis, point, rate_est}`
  - **生成后校验**：选项数=4、答案在 0-3、题干非空；再入"待审核"区，标注 `is_ai=1`
- 难度控制：按正确率分档（≥80 简单 / 60-80 中等 / 40-60 较难 / <40 困难）映射到 prompt 里的"计算量/陷阱数量"

### 4.4 模拟卷生成（Paper Gen）

- 输入：卷种（国考副省/地市/执法/省考联考/江苏 A…）+ 模块题量（可默认 PAPER_CONFIGS）+ 范围（全部/真题/模考）+ 难度偏好
- 逻辑：
  1. 工具查 `paper_configs.json` 得模块题量（如江苏 A：常识15/言语45/数量20/判断45/资料10 = 135）
  2. **优先从题库按考点均衡抽样**（保证知识覆盖），不足部分用"新题生成"补齐
  3. 输出：试卷 JSON（题目列表 + 答案 + 解析）+ 可导出 PDF（复用 2.1 修复后的打印管线）
- 与现有 `buildPaper()` 差异：增加**考点均衡 + 难度曲线**控制（避免一卷全是简单题）

### 4.5 申论批改（Essay Grading）—— 辅助反馈，非官方分数

- 输入：题目（或题 id）+ 用户作答文字 +（可选）字数/时限
- 流程：
  1. 工具取题目要求与参考要点
  2. 模型按**测评要素**逐项打分（要点完整性 / 结构条理 / 语言表达 / 卷面印象【只能估】）
  3. 输出：总分与分项（以星级/百分制呈现，**明确标注"AI 参考分"**）+ 逐项改进建议 + 高分改写示范（可选）
- 防幻觉：
  - 分数区间固定 0-100，带分项权重（如 归纳概括 40% / 综合分析 30% / 表达 30%）
  - 要求模型引用作答原文作为打点依据（"你在第 3 段写了……对应要点②"）
  - 提供"参考要点"给模型对照，不凭空捏造标准
- 大作文：额外输出标题吸引力、结构（总-分-总）、论证充分性、结尾升华

### 4.6 个人画像联动（Prof）

- 输入：用户做题数据（上岸通 `store.attempts` 或独立 CLI 的学习日志）
- 输出：
  - 薄弱考点 TOP（按正确率+次数加权）
  - 建议练习："你的【判断推理-图形推理】正确率 45%（低于全库 69%），建议先做 10 道专项"
  - 自动触发 4.3/4.4 生成针对性练习
- 数据格式：复用上岸通 `attempts` 结构（mod/point/rate/dur/ok）

## 5. 工具层（function calling 清单）

| 工具名 | 参数 | 返回 | 用途 |
|---|---|---|---|
| `search_bank` | `q, mod?, point?, rate_min?, rate_max?, src?, limit` | 题目列表（id/stem 摘要） | 检索题库 |
| `get_question` | `qid` | 完整题目（含答案/解析/材料/图） | 取题详情 |
| `get_paper_structure` | `paper_type` | 卷种模块题量/时限 | 出卷/讲解结构 |
| `get_outline` | `mod?` | 官方测查要素 | 讲解/出题对齐大纲 |
| `get_shenlun_material` | `cat?, keyword?` | 素材条目 | 申论讲解/批改引用 |
| `get_weakpoints` | `user_id?` | 薄弱考点列表 | 画像联动 |
| `compose_paper` | `paper_type, scope, difficulty?` | 试卷 JSON | 组卷 |
| `grade_essay` | `question, answer, outline?` | 批改结果 | 申论批改 |

> Agent 的"聪明"来自：**先工具检索真实数据，再模型组织语言**。所有回答可追溯（附题目 id/来源）。

## 6. Prompt 工程要点

### 6.1 系统提示（System Prompt）骨架

```
你是"上岸通"公考 AI 助教，专精公务员考试（行测+申论）。
能力边界：
- 行测：只讲你检索到的真实题目；不凭空捏造题干/选项/答案。
- 申论：批改是 AI 参考意见，不是官方成绩；标注"仅供参考"。
- 出题：只做考点一致的新题，选项 4 个、答案唯一，输出 JSON，经校验后标 is_ai。
工具：需要数据时调用工具，禁止编造。
语气：耐心、鼓励、条理；答错先共情再分析。
安全：不输出个人可识别信息；不鼓励应试作弊（如代考）。
```

### 6.2 关键 Prompt 技巧

| 场景 | 技巧 |
|---|---|
| 提示分级 | 用"3 档开关"变量控制泄露程度，由工具侧决定给到第几档 |
| 新题生成 | few-shot 给 1 道母题作参照 + 强制 JSON schema + 生成后程序校验 |
| 申论批改 | 要求"引用原文为证"，分数与分项绑定测评要素 |
| 多选 | 明确要求逐选项对错判断，输出 `[A,B]` 数组 |
| 资料来源 | 每次引用题目必须带 `[题目 #gk00001｜2025·国考]` 式出处 |

## 7. 模型接入层

### 7.1 多供应商抽象（OpenAI 兼容）

```toml
# ~/.satan_ai/config.toml
[provider.ark]
base_url = "https://ark.cn-beijing.volces.com/api/v3"
model = "deepseek-v4-flash"
key_env = "ARK_API_KEY"

[provider.worldcodes]
base_url = "https://worldcodes.online/v1"
model = "wc-sonnet"

[provider.testvideo]
base_url = "https://testvideo.site/v1"   # 需走 Clash 代理
model = "gpt56-sol"
proxy = "http://127.0.0.1:7897"
```

- 统一 OpenAI Chat Completions 协议（含 `tools`/`tool_calls`）
- 模型自动降级链：主模型失败 → 备用模型（如 ark-flash → worldcodes → testvideo）
- 成本控制：提示/讲解用便宜模型，申论批改/出题用强模型（可配置）

### 7.2 独立运行形态

| 形态 | 命令 | 说明 |
|---|---|---|
| CLI | `satan-ai hint gk00001` / `satan-ai chat` | 交互式终端助教 |
| HTTP | `satan-ai serve --port 8765` | FastAPI，供任意前端/脚本调 |
| 网页 | `satan-ai web` | 内置单页前端（可独立部署） |
| 嵌入 | 上岸通前端 fetch `/api/ai/v1/*` | 复用 `docs/ai_proxy_contract.yaml` |


## 8. 数据、隐私与安全

| 项 | 策略 |
|---|---|
| API Key | 只存服务端 config / 用户本地 `~/.satan_ai/config.toml`；**绝不放前端** |
| 用户作答数据 | 默认本地存储；只有用户主动开启"云端同步"才上传 |
| 个人信息 | 不向模型发送真实姓名/手机号；日志脱敏 |
| 版权 | 题库解析版权归原题库方（粉笔等），AI 生成内容标注来源；新题标注 `is_ai` |
| 伦理 | 提示不泄答案、批改不冒充官方、出题经校验、可追溯来源 |
| 速率/费用 | 每请求带预算上限；长对话按轮数/长度截断 |

## 9. 验收标准

| 模块 | 验收样例 |
|---|---|
| 智能提示 | 给国考数量题，级别1 只说考点、级别2 只讲思路，**全程不出现最终数字** |
| 深度解答 | 给一道错题，输出含"每个选项对/错原因"+"同类题建议"，引用的题号真实存在 |
| 类题推荐 | 输入"工程问题-效率合作"母题，返回 5 道同考点题，点开均有完整解析 |
| 新题生成 | 生成 10 道同考点新题，程序校验 100% 通过（4 选项/答案合法/题干非空），人工抽查 ≥8/10 可用 |
| 模拟卷 | 用江苏 A 模板生成 135 题卷，模块题量与 PAPER_CONFIGS 一致（常识15/言语45/数量20/判断45/资料10），考点均衡不重复 |
| 申论批改 | 给一篇 800 字大作文，输出分项评分（引用原文为证）+ 3 条具体改进建议 + 明确"AI 参考分" |
| 独立运行 | `satan-ai chat` 在本机无上岸通也能独立完成"提示+讲解+出题"全流程 |
| 性能 | 类题推荐 < 500ms；新题生成 < 30s（弱模型）或 < 60s（强模型） |

## 10. 实施路线图

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **3.0-A 基础** | 建 `satan_ai` 包骨架；题库转 SQLite；工具层 8 个工具；LLM 接入层+降级链；CLI 可跑"检索+取题" | 无 |
