# 上岸通 3.0：行测 / 申论 AI 探究与接口草案

> 状态：**研究与技术预留，不在 2.0 默认启用**  
> 原则：AI 是“讲解与反馈助手”，不是官方裁判；所有 AI 内容必须可识别、可追溯、可撤回。

## 1. 结论先行

### 1.1 值得做，按这个优先级

1. **行测分级提示**：先提示考点，再提示思路，再提示关键一步；默认不直接泄露答案。
2. **解析追问**：用户看不懂现有解析时，结合题干、选项、标准答案与原解析进行针对性解释。
3. **申论结构化反馈**：按评分维度指出“材料依据—问题—修改动作”，先做形成性反馈，不宣传为官方分数。
4. **申论逐段改写建议**：展示原句、问题、建议和一份参考改写，用户自主采纳。
5. **AI 生成变式题**：只能进入“AI 练习区”，经过自动校验或人工审核后才能进入主题库。
6. **申论分数估计**：最后实装；必须先完成与双人评分样本的校准实验。

### 1.2 2.0 只预留、不实装的部分

- 预留统一 `/api/ai/v1/*` 契约与前端 feature flag。
- 题目、用户答案、评分反馈均采用结构化 JSON。
- 保存 `model / promptVersion / rubricVersion / requestId`，保证结果可复现和回溯。
- 不把任何模型 API Key 写进浏览器代码；必须由服务端代理调用。
- 默认不上传真实姓名、手机号、准考证号等个人信息。

## 2. 为什么不能把 AI 分数当“真实申论分数”

2026 年国考大纲把申论能力拆为阅读理解、综合分析、提出和解决问题、文字表达等维度；不同职位类别还存在贯彻执行、依法办事、公共服务等差异。[1] 因此，申论反馈必须按**题目类型、职位类别和评分维度**分别建 rubric，不能只给一个笼统总分。

自动作文评分研究表明，部分大模型能获得较好的评分一致性，但模型间差异明显，同一模型也会随时间、更新和重复运行产生波动；研究者明确建议在具体教育场景内自行做效度与信度验证。[2] 所以上岸通 3.0 的正确定位应是：

- **形成性反馈**优先于高风险打分；
- 分数展示为“AI 估计区间”，而不是单点官方分；
- 每个扣分判断都必须引用用户原文与给定材料；
- 无材料依据时必须输出 `insufficient_evidence`，不能编造阅卷规则或材料事实；
- 正式上线前，用同一批答卷做“模型重复评分 + 双人评分”校准。

## 3. 产品能力设计

## 3.1 行测 AI 助手

### A. 分级提示（推荐最先实装）

| 层级 | 用户看到什么 | 是否泄露答案 |
|---|---|---|
| H1 考点提示 | “这题考查增长率与基期量关系” | 否 |
| H2 路径提示 | “先由现期量和增长率反推基期量” | 否 |
| H3 关键一步 | 给出应代入的公式或排除规则 | 尽量否 |
| H4 完整讲解 | 逐项分析并给出答案 | 是，需用户主动点开 |

**防泄露约束：** H1–H3 的输出 schema 不允许出现 `answer` 字段；服务端还要扫描标准答案字母、选项原文和“正确选项是”等表达，命中则重试或降级。

### B. 解析追问

输入：题干、选项、标准答案、原解析、用户选择、用户问题。  
输出：

- 用户卡住的具体步骤；
- 用更简单语言重讲；
- 错误选项为什么有诱惑性；
- 一条可迁移到同类题的方法；
- 最后可选一题微型检验题。

### C. AI 变式题

生成后必须经过以下闸门：

1. schema 校验：选项数、答案格式、解析字段完整；
2. 一致性校验：由第二次独立模型调用只做“题目是否唯一可解”；
3. 与原题相似度检测，避免只是换数字或复制；
4. 标记 `origin: ai_generated`、模型、提示词版本；
5. 默认不进入主题库统计，不影响“真题正确率”。

## 3.2 申论 AI 助手

### A. 小题反馈

固定输出五层：

1. **任务识别**：归纳概括 / 综合分析 / 提出对策 / 贯彻执行；
2. **材料覆盖**：引用材料编号或句段，列出已覆盖与遗漏要点；
3. **结构评价**：分类是否合理、层次是否清晰、是否重复；
4. **表达评价**：准确、规范、简明、字数与身份语气；
5. **修改行动**：按优先级给 3–5 条可执行建议。

### B. 大作文反馈

建议采用分析型 rubric，而不是直接“模型凭感觉打分”：

- 立意与题意一致性；
- 材料联系与论据质量；
- 结构完整性与段落功能；
- 论证链条；
- 政务表达与语言规范；
- 字数、标题、错别字等形式项。

输出总分时必须同时提供：

- `scoreRange`（如 62–68）而非伪精确单分；
- 每维得分区间；
- 至少 3 条原文证据；
- 不确定性与缺失信息；
- “仅用于练习反馈，非官方阅卷结果”声明。

### C. 双阶段批改

1. **Evidence Pass**：只抽取材料要点、用户原文证据和形式事实，不评分；
2. **Judge Pass**：只基于第一阶段证据和 rubric 打分、反馈。

这样可减少“先产生印象再找理由”的问题，也便于对每个判断做溯源。

## 4. 数据与评测方案

### 4.1 最小校准集

- 每种申论题型至少 100 份答卷；
- 每份由 2 名熟悉申论评分的人工评分者独立评分；
- 分歧过大的答卷由第 3 人仲裁；
- 保存题目、材料、职位类别、rubric 版本、维度分和评语；
- 去除姓名、手机号、单位、准考证号等可识别信息。

### 4.2 上线门槛

| 指标 | 建议门槛 | 用途 |
|---|---:|---|
| 同一答卷重复评分绝对差 | 80% 样本 ≤ 3 分 | 稳定性 |
| 与人工平均分 MAE | ≤ 5 分（100 分制） | 分数误差 |
| 各维度与人工相关性 | ≥ 0.70 | 构念一致性 |
| 引用证据准确率 | ≥ 95% | 防幻觉 |
| H1–H3 答案泄露率 | < 1% | 学习有效性 |
| 严重事实幻觉率 | < 1% | 安全性 |

> 这些是产品验收建议，不是现成研究结论；需用上岸通自己的申论样本验证后调整。

### 4.3 回归集

每次切模型、改系统提示词、改 rubric 后都跑固定回归集，记录：

- 分数漂移；
- 维度漂移；
- 证据引用错误；
- 答案泄露；
- 输出 schema 失败；
- 延迟与费用。

任何模型升级都不能静默替换，必须形成新的 `modelSnapshot`。

## 5. 架构方案

```text
上岸通 PWA
  └─ POST /api/ai/v1/hints | explain | essay/review | generate
       ├─ 鉴权 / 限流 / 配额
       ├─ PII 脱敏与输入长度检查
       ├─ Prompt + Rubric 版本选择
       ├─ 模型路由（主模型 / 降级模型）
       ├─ JSON Schema 校验与泄露扫描
       ├─ 可选第二模型审校
       └─ 返回结构化结果 + requestId + 版本元数据
```

### 5.1 为什么一定要代理层

- 浏览器里放 Key 会泄露；
- 需要统一限流、费用控制与模型切换；
- 需要服务端做提示词保密、结构化校验、内容安全与审计；
- 需要严格控制是否留存用户作文。

### 5.2 隐私默认值

《生成式人工智能服务管理暂行办法》要求保护用户输入和使用记录，不得收集非必要个人信息，不得非法留存能够识别用户身份的输入与记录，并要求提升生成内容的准确性和可靠性。[3] 因此建议：

- `storeText=false` 为默认值；服务端完成请求后不保存作文正文；
- 只保存匿名化指标、hash、模型版本、耗时和错误码；
- 用户主动选择“保存到学习档案”时，优先保存在浏览器本地；
- 用户可一键导出和删除全部 AI 记录；
- 日志禁止记录完整 prompt、作文与手机号；
- 第三方模型调用前显示数据去向与用途。

## 6. API 契约摘要

完整 OpenAPI 草案见：`docs/ai_proxy_contract.yaml`。

### 6.1 通用响应

```json
{
  "requestId": "air_01...",
  "task": "essay_review",
  "modelSnapshot": "provider/model@2026-08",
  "promptVersion": "essay-review-v1",
  "rubricVersion": "guokao-shenlun-v1",
  "result": {},
  "warnings": [],
  "usage": {"inputTokens": 0, "outputTokens": 0, "latencyMs": 0}
}
```

### 6.2 失败时必须可降级

- AI 不可用：原题解析与静态评分表仍可使用；
- schema 无效：最多重试一次，然后返回明确错误；
- 证据不足：返回 `insufficient_evidence`，不猜分；
- 超额：返回本地可执行的学习建议，而不是空白页。

## 7. 分期路线

### 2.0（当前）

- 完成接口契约、feature flag 与研究文档；
- 不启用真实模型调用；
- 收集匿名的“用户在哪里看不懂解析”按钮事件，为 3.0 选场景。

### 3.0-alpha

- 行测 H1–H4 分级提示；
- 解析追问；
- 申论小题结构化反馈，不给总分；
- 建立 100–300 份人工校准集。

### 3.0-beta

- 申论双阶段批改；
- AI 估分区间；
- 模型重复评分与证据审校；
- 变式题仅在 AI 练习区。

### 3.0 正式版

仅在校准指标达标后启用估分；持续保留“AI 反馈、非官方评分”标识和人工反馈入口。

## 8. 验收标准

- [ ] 浏览器源码、localStorage、Network 响应中均无供应商 API Key。
- [ ] 所有 AI 响应通过 JSON Schema。
- [ ] 行测 H1–H3 不出现标准答案或正确选项原文。
- [ ] 申论每项扣分都能定位到原文或材料证据。
- [ ] 模型/提示词/rubric 任一变化均有新版本号并跑回归集。
- [ ] AI 断网或超额时，上岸通核心刷题、组卷、导出、画像功能仍完整可用。
- [ ] 用户可以查看、导出、删除自己的 AI 记录。
- [ ] 未经校准不得展示“官方分”“真实分”等误导性措辞。
