# 致泽学堂 UI 全面改版设计文档（讨论稿）

> **For Hermes:** 本文是设计锁定前的规划文档。本轮只定义品牌、信息架构、页面骨架、组件与接口边界，不实施生产代码。待用户修改确认后，再按任务拆分执行。

**项目新名称：** 致泽学堂
**名称寓意：** 取“致知笃行、致国泽民”之意——先以学习求知、以训练成事，最终将能力用于公共服务。
**推荐主 Slogan：** **以学致知，以行泽民**
**产品副标题：** 公考学习与能力成长学堂
**设计方向：** 以方案一“墨蓝书院”为主，吸收方案二的高效工作台与方案三的成长反馈，但避免做成后台系统或过度游戏化产品。

---

## 1. 文档目标

本设计文档用于在正式开发前确认以下内容：

1. 将“上岸通”完整更名为“致泽学堂”；
2. 建立偏古风、但不过度仿古的现代书院品牌系统；
3. 重构首页、一级导航和二级页面的信息架构；
4. 保留现有核心功能入口，不在本轮触碰题库数据内容；
5. 为申论和 AI 功能保留一、二级页面及服务接口，暂时移除具体内容；
6. 明确桌面端、移动端、空状态、加载状态和无障碍标准；
7. 形成后续可直接拆分实施和验收的规范。

### 1.1 本轮设计范围

- 品牌命名、Slogan、图标、色彩、字体与视觉语言；
- 全局导航、首页和二级页面骨架；
- 行测、成长、申论、AI 学伴、个人中心的信息架构；
- 关键组件和状态规范；
- 申论与 AI 的前端服务边界和占位接口；
- 响应式与无障碍规范；
- 后续实施顺序和验收条件。

### 1.2 本轮不做

- 不直接替换生产 UI；
- 不修改题库数据、答案和解析；
- 不接入真实申论内容；
- 不接入真实大模型或 AI 服务；
- 不重写题库缓存与答题业务；
- 不迁移、删除或重置用户已有学习数据；
- 不决定所有插画与动效细节。

## 2. 品牌设计

## 2.1 品牌定位

“致泽学堂”不是单纯的刷题工具，也不是传统在线课程网站，而是一间面向公考学习者的数字书院：

- **可信**：数据、来源、进度和学习结果可解释；
- **沉静**：降低考试焦虑，不用高饱和色和夸张激励刺激用户；
- **务实**：每次进入都知道今天该做什么；
- **成长**：既看到分数，也看到阶段进步、能力变化和学习节奏；
- **有志向**：品牌表达公共服务理想，但不使用空泛、宏大的口号压迫用户。

### 品牌关键词

`现代书院`、`墨蓝`、`纸张`、`水纹`、`笃行`、`成长`、`克制`、`可信`

### 不采用的风格

- 大红大金、牌匾式“伪古风”；
- 水墨背景大图压住功能内容；
- 过多毛笔字，影响正文阅读；
- 游戏化等级、勋章和连续弹窗轰炸；
- 传统 SaaS 后台式密集表格；
- 直接使用“龙、官帽、国徽、印章公文”等容易产生误解的符号。

## 2.2 品牌命名层级

| 层级 | 文案 | 使用位置 |
|---|---|---|
| 主品牌 | 致泽学堂 | Logo、启动页、侧栏、标题栏 |
| 主 Slogan | 以学致知，以行泽民 | 首次进入、品牌页、桌面侧栏底部 |
| 产品副标题 | 公考学习与能力成长学堂 | SEO、关于页、分享卡片 |
| 简称 | 致泽 | 移动端窄空间、通知文案 |
| AI 子品牌 | 致泽 AI 学伴 | AI 一级入口和占位页 |

## 2.3 Slogan 方案

### 推荐：以学致知，以行泽民

- “致知”对应学习与判断；
- “行”对应训练、实践与未来履职；
- “泽民”回应“致泽学堂”的命名含义；
- 八字对仗，适合页眉、开屏和分享物料；
- 语气克制，不直接承诺“上岸”。

### 备选一：致知笃行，泽民于心

更偏书院气质，情绪温和，但“泽民于心”的动作感稍弱。

### 备选二：学以致用，志在泽民

目标感更强、更直白，适合活动页，但品牌独特性不及推荐方案。

### 备选三：每日精进，终有所成

更贴近日常学习，但未体现“致泽”的名称来源，可作为首页成长区辅助文案。

## 2.4 品牌图标概念：泽印书页

### 构图

采用一个**圆角方形现代印记**，不直接照搬传统红印章：

1. 上部一条轻微上扬的横线，象征“学堂檐口”；
2. 中部两片对开的负形书页，象征学习与求知；
3. 下部三道由短到长的水纹，象征“泽”；
4. 书页中缝与水纹共同形成抽象的字母 `Z` 动势；
5. 外框不闭合一角，表达学习仍在持续、系统保持开放。

### 图标版本

| 版本 | 用途 | 细节 |
|---|---|---|
| 标准横版 | 桌面侧栏、登录/启动页 | 图标 + “致泽学堂” + Slogan |
| 紧凑横版 | 顶部栏 | 图标 + “致泽学堂” |
| 独立图标 | App 图标、Favicon、移动端 | 仅保留檐口、书页、水纹 |
| 单色版 | 打印、PDF、水印 | 100% 墨蓝或黑色 |
| 反白版 | 深色侧栏 | 米白图形，不使用纯白 |

### 图标色彩

- 默认底色：墨蓝 `#17384C`
- 图形主色：纸白 `#F5EEDF`
- 点睛色：黍金 `#B58A4B`
- 特殊印记：朱砂 `#A64B3C`，只用于小面积状态或品牌印记

### 图标摆放

- 桌面端：左侧导航顶部，距容器上边 24px；
- 移动端：首页顶部左侧使用独立图标 + 品牌名；
- 首页 Hero 不重复放超大 Logo，只显示问候与成长内容；
- 答题界面只在标题栏保留 20px 单色图标，避免干扰；
- 申论和 AI 占位页可使用低对比度水印图形；
- Favicon 使用独立图标，不再使用单个“上”字。

## 3. 视觉系统

## 3.1 总体方向

采用“**现代书院 + 清晰工作台 + 温和成长反馈**”三层融合：

- 方案一贡献：墨蓝、米纸白、宋体标题、阅读沉浸和品牌辨识度；
- 方案二贡献：双栏工作台、任务优先、能力矩阵和专业筛选效率；
- 方案三贡献：今日闯关、能力值、正向反馈、移动端路线感；
- 最终界面必须首先是高效学习工具，其次才是古风视觉表达。

## 3.2 色彩 Token

| Token | 色值 | 用途 |
|---|---:|---|
| `--ink-900` | `#102B3A` | 深色侧栏、标题 |
| `--ink-700` | `#17384C` | 主品牌色、主按钮 |
| `--ink-500` | `#315B6F` | 次级操作、图表 |
| `--paper-100` | `#FAF7F0` | 页面主背景 |
| `--paper-200` | `#F3EDDF` | 卡片、分区背景 |
| `--paper-300` | `#E7DECC` | 边框、分割线 |
| `--charcoal` | `#283238` | 正文 |
| `--muted` | `#66747A` | 辅助文字，需满足 WCAG AA |
| `--gold` | `#B58A4B` | 品牌点睛、成长进度 |
| `--vermilion` | `#A64B3C` | 错误、重要印记，禁止大面积使用 |
| `--jade` | `#4F7B70` | 正确、完成、稳定增长 |
| `--sun` | `#D99A5B` | 今日任务与暖反馈，小面积使用 |

### 色彩使用比例

- 纸白与浅米背景：约 70%；
- 墨蓝结构和正文：约 20%；
- 黍金、朱砂、玉青、暖橙状态色：总计不超过 10%。

## 3.3 字体

### 品牌与标题

```css
font-family: "Noto Serif SC", "Source Han Serif SC", "Songti SC", "SimSun", serif;
```

用于：品牌名、一级页标题、分区标题、重要数字旁的短标签。

### 正文与控件

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", sans-serif;
```

用于：正文、题干、选项、表单、按钮、统计和移动端内容。

### 原则

- 题干和解析不使用宋体，保证长时间阅读清晰；
- 不依赖必须联网加载的字体，保持离线可用；
- 数字使用系统等宽数字特性 `font-variant-numeric: tabular-nums`；
- 正文字号桌面不低于 15px，移动端不低于 14px；
- 底部导航不再出现 9px 字号。

## 3.4 形状与材质

- 卡片圆角：12–16px，不使用夸张大圆角；
- 主按钮圆角：10px；
- 小标签可使用 999px 胶囊形；
- 边框使用纸张色阶，不用灰色硬线；
- 阴影极轻，仅用于浮层和重要悬浮卡；
- 页面分区可用一条“书页折线”或水纹细线，不铺水墨纹理图片；
- 朱砂印记只用于“已完成”“今日”等短标签。

## 3.5 动效

- 页面切换：160–220ms 淡入与 4–8px 位移；
- 能力值加载：600ms 数字递增，仅首次出现；
- 今日闯关完成：进度条平滑增长 + 一次轻微印记出现；
- 禁止金币飞散、持续闪烁和大面积庆祝动画；
- 尊重 `prefers-reduced-motion`，关闭非必要动画。

## 4. 信息架构

## 4.1 一级导航

桌面端建议使用左侧常驻导航；移动端使用五项底部导航。

| 一级页面 | 桌面导航 | 移动导航 | 核心作用 |
|---|---:|---:|---|
| 首页 | 是 | 是 | 今日任务、成长反馈、快速继续 |
| 行测研习 | 是 | “行测” | 刷题、模考、组卷、检索 |
| 学习成长 | 是 | “成长” | 错题、能力、记录 |
| 申论书房 | 是 | “申论” | 仅保留页面骨架和接口 |
| 致泽 AI 学伴 | 是，特殊入口 | 首页悬浮入口/二级页 | 仅保留页面骨架和接口 |
| 我的 | 是 | 是 | 数据、缓存、设置、关于 |

### 为什么移动端不把 AI 作为第六个底栏项

移动端底栏最多保留五项以确保触摸面积和识别度。AI 使用：

- 首页能力卡右上角“问学伴”；
- 行测题目解析区“问此题”；
- 申论页面“请学伴协助”；
- 顶部或页面右下角 48px 的墨蓝圆形入口；
- 所有入口最终汇入“致泽 AI 学伴”一级页面。


- 左侧栏宽度：224–248px；
- 主内容最大宽度：1320px；
- 右侧学习栏只在首页和行测工作台出现；
- 阅读页面（题干、解析、申论）切换为居中单栏，正文最大宽度 760px；
- 左侧栏可折叠为 72px 图标模式，但首版可暂不实现。

## 5.2 平板端（768–1099px）

- 侧栏缩为 80px 图标导航；
- 主区与右栏可改为上下排列；
- 高级筛选放入抽屉；
- 首页能力卡和今日路线保持双列，窄时转单列。

## 5.3 移动端（≤ 767px）

- 顶部仅保留 Logo、当前页标题和一个 AI 入口；
- 底部五项导航：`首页 / 行测 / 成长 / 申论 / 我的`；
- 页面底部增加安全区 `env(safe-area-inset-bottom)`；
- 卡片左右边距 16px；
- 题目页保持全屏沉浸，不展示首页导航；
- 筛选、组卷配置、AI 对话使用底部 Sheet；
- 所有主要触摸目标不小于 44×44px。

## 6. 首页详细设计

首页是三套方案融合的核心页面，目标是让用户在 5 秒内回答：

1. 我今天应该做什么？
2. 我最近有没有进步？
3. 我下一步从哪里继续？

## 6.1 首页首屏结构

```text
[早安，学习者]                         [连续学习 7 天]
今日宜稳步精进

┌──────────────────────────────────────────────────────┐
│  致学力 684                          较上周 +18       │
│  你已超过上周的自己                                  │
│  [能力进度弧线/水纹]      目标 720                    │
│  [继续今日闯关]          [查看能力图谱]                │
└──────────────────────────────────────────────────────┘

今日闯关  2/3
① 言语专项 20题  已完成
② 判断推理 15题  进行中
③ 错题温习 10题  待开始

[薄弱点建议]  [最近模考]  [本周节奏]
```

## 6.2 “你已超过”能力反馈

用户明确喜欢方案三的“你已超过”设计，保留但必须避免伪造群体数据。

### 默认离线文案

- **你已超过上周的自己**
- 本周致学力提升 `+18`
- 连续完成 `4` 个学习日

### 有真实群体数据后

只有接入明确、匿名且可解释的统计接口后，才显示：

- **你已超过 72% 的同阶段学习者**
- 辅助说明：“基于近 30 天完成同类训练的匿名用户样本”
- 提供“数据如何计算”入口

### 空数据状态

- 标题：“从今天开始记录你的成长”
- 说明：“完成首组 10 道题后生成第一份能力画像”
- 主按钮：“开始首次闯关”

## 6.3 能力值命名

推荐使用 **“致学力”** 作为品牌化展示名，旁边保留解释：

> 致学力：根据正确率、难度、稳定性、速度和复习完成度综合形成的学习能力趋势值，不等同于考试分数。

### 计算展示原则

- 不承诺精确预测考试成绩；
- 展示趋势比绝对值更重要；
- 每次变化可解释，例如“判断推理稳定性 +6”；
- 没有足够数据时不显示虚假精确数字；
- 用户可关闭能力值和同伴比较。

## 6.4 今日闯关

吸收方案三的成长路线，但采用方案二的任务效率：

- 每天最多 3 个主任务；
- 每个任务显示题量、预计时间、模块、状态；
- 完成后使用小面积朱砂“已成”印记；
- 支持“一键继续”上次中断的任务；
- AI 学习计划未来可写入任务，但必须标注来源为“AI 建议”；
- 用户可手动调整，不强制执行。

## 6.5 首页右侧栏（桌面）

- 今日剩余任务；
- 最近一次继续学习；
- 本周学习时间；
- 快捷入口：错题、模考、组卷、回填；
- “问致泽 AI”入口。

移动端按顺序折叠到主内容流，不使用横向拥挤小卡片。

## 7. 一级与二级页面规范

## 7.1 行测研习一级页

采用方案二的效率工作台，但视觉使用墨蓝书院：

- 顶部：本周行测概览、继续上次训练；
- 主区：专项练习、每日课业、模拟考场；
- 次区：智能组卷、题库检索、纸卷回填；
- 右栏：模块能力矩阵、今日建议；
- 不在首页暴露所有筛选项；
- 高级筛选进入二级页。

### 专项练习二级页

- 模块、考点、来源、难度、题量；
- 最近使用条件；
- 空结果明确提示；
- 主操作固定为“开始练习”；
- 完整题库加载状态可见但不阻塞基础题库。

### 模拟考场二级页

- 真实模板、智能模板、自定义三类入口；
- 考试时长、题量、模块结构清晰；
- 开考前显示规则确认；
- 进行中保持全屏沉浸；
- 交卷后只显示一个结果对话框。

### 题库检索二级页

- 搜索词为主，筛选器为辅；
- 桌面端左侧筛选、右侧结果；
- 移动端筛选使用底部 Sheet；
- 单题点击进入单题；

## 9. 致泽 AI 学伴：仅保留页面与接口

## 9.1 定位

AI 是学习辅助层，不是首页聊天机器人。其职责按优先级为：

1. 解释当前题目与错误原因；
2. 根据真实学习数据提出下一步建议；
3. 协助制定可修改的学习计划；
4. 未来协助申论分析与反馈；
5. 无证据时明确拒答，不伪造题目来源或学习数据。

## 9.2 AI 一级页

保留以下骨架：

- 顶部品牌：“致泽 AI 学伴”；
- 服务状态区；
- 三个二级入口：题目精讲、学习规划、对话记录；
- 对话输入框预览；
- 隐私提示：“发送前可选择是否附带当前题目和学习画像”；
- 未接入状态：“AI 学伴正在筹备，当前不会发送任何数据。”

## 9.3 二级页面骨架

### 题目精讲

- 当前题目摘要区；
- “我的答案 / 正确答案 / 考点”结构预留；
- AI 回答区和证据引用区；
- “换个角度解释”“生成同类练习”按钮显示为不可用预览。

### 学习规划

- 学习目标、可用时间、考试日期输入骨架；
- AI 建议区；
- 计划必须先由用户确认，不能直接写入今日任务；
- 显示建议依据和使用了哪些学习数据。

### 对话记录

- 会话列表、日期、主题和删除入口；
- 未接入时不创建假会话。

## 9.4 AI 前端服务接口（预留）

```ts

  chat(input: ChatRequest): Promise<ChatResponse>;
  explainQuestion(input: ExplainRequest): Promise<ExplainResponse>;
  proposeStudyPlan(input: StudyPlanRequest): Promise<StudyPlanProposal>;
```

### 与现有公考 AI Agent 的兼容边界

首期只要求适配统一聊天入口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/ai/v1/status` | 能力、模型、版本、可用状态 |
| POST | `/api/ai/v1/chat` | 统一问答入口，后端基于 context 决定题目精讲或学习建议 |

建议请求：

```json

  "conversation_id": null,
  "message": "请解释我为什么会选错这道题",

    "question_id": "q_123",
    "current_view": "quiz_result",

  }
```

建议响应：


### AI 安全与隐私要求

- 默认不发送完整学习记录；
- 每次附带学习画像时明确提示；
- 不在浏览器代码中写 API Key；
- 服务不可用时保持普通刷题完全可用；
- AI 输出与题库原始解析视觉上区分；
- 引用题目时保留来源与题号；
- 无依据时显示“暂无法根据现有资料回答”；
- 用户可删除会话；
- AI 建议不能自动修改错题、统计或学习任务。

## 10. 关键组件规范

## 10.1 品牌侧栏

- Logo + 品牌名固定在顶部；
- 当前导航使用米白底上的墨蓝块或深色侧栏上的金色细线；
- 不只依赖颜色，增加左侧标识和 `aria-current`；
- 底部显示 Slogan 和版本入口；
- AI 入口使用小型星芒/水纹图标，不使用彩色渐变球。

## 10.2 首页能力卡

- 全站唯一可使用轻微渐变的主卡；
- 数字比文案更突出，但不超过 48px；
- 包含数据解释入口；
- 群体百分位不可在无数据时展示；
- “超过自己”与“超过同阶段学习者”是两种不同状态。

## 10.3 今日闯关卡

- 三个状态：待开始、进行中、已完成；
- 每个任务只有一个主操作；
- 不使用锁链、宝箱、金币；
- 完成印记用小面积朱砂色；
- 支持键盘和读屏描述。

## 10.4 数据卡与图表

- 图表必须同时提供文字摘要；
- 不使用红绿作为唯一信息；
- 空数据不画 0 值雷达图；
- 能力图优先横向条形图和趋势线；
- 雷达图仅作为概览，不能代替具体数据。

## 10.5 按钮

- 主按钮：墨蓝底、纸白字；
- 次按钮：透明底、墨蓝边；
- 危险按钮：默认中性，确认时才使用朱砂；
- 禁用按钮必须有解释，不只是降低透明度；
- 点击区域至少 44×44px。

## 10.6 空状态

统一结构：

1. 简化品牌水纹图；
2. 明确标题；
3. 一句话说明为何为空；
4. 一个可执行主操作，或“功能筹备中”说明；
5. 不出现虚假示例数据。

## 12. 响应式与无障碍硬性标准

1. 允许浏览器缩放，不设置 `user-scalable=no`；
2. 所有输入、选择器都有可访问名称；
3. 所有可点击元素使用原生 button/link；
4. 模态打开后隔离背景，焦点进入对话框，关闭后恢复；
5. 主要触摸目标 ≥ 44×44px；
6. 正文与背景对比度 ≥ 4.5:1；
7. 非文字控件对比度 ≥ 3:1；
8. 当前导航同时使用形状、文字或 ARIA 状态，不只靠颜色；
9. 320px 宽度不得出现页面级横向滚动；
10. 支持 `prefers-reduced-motion`；
11. 图表必须有文字摘要；
12. AI 和申论不可用状态可被读屏识别；
13. 键盘可完成首页 → 行测 → 开始练习 → 作答 → 结果 → 返回全流程。

### 20.4 点击水纹涟漪

- 主按钮、导航和可点击功能卡在点击坐标生成一次性淡墨水纹；
- 单次 420–600ms，最多两圈，峰值透明度不高于 16%；

- 键盘触发时使用弱化的居中涟漪，但焦点框必须持续可见；
- “我的书斋 → 显示与无障碍”提供独立的“点击涟漪”开关；
- 同一设置区提供“古风背景”“页面淡入”开关；
- 系统开启 `prefers-reduced-motion` 时，涟漪和非必要页面动效自动关闭。

### 20.5 首页直接问泽

首页不再只有“进入 AI”按钮，而是提供可直接使用的问泽对话框：

```text
问泽 · 致泽学堂 AI 学伴
想从哪里继续？可以问我今日安排、薄弱点或一道具体题。
[今天先练什么] [解释上次错题] [我的薄弱点]
[🎙] [输入想问的问题........................] [发送]
当前附带：学习画像 □
```

- 支持文字输入、推荐问题、发送、停止生成、清空和语音输入；
- 默认只发送用户输入，不默认附带完整学习画像；
- 用户首次勾选学习画像时必须解释范围并确认；
- 服务未接入时允许演示输入状态，但明确显示“问泽尚未接入”，不能生成假回答；
- 桌面端可置于首页右栏下部或主栏中部；移动端应位于前两屏内。

### 20.6 每道题解析下方直接问泽

每道题的结果页、回顾页和单题检索详情都在**题库原始解析之后**加入：

```text
[题库原始解析与来源]

问泽讲解 · AI 辅助
[为什么不能选 B] [换个角度讲] [总结这个考点]
[对话历史]
[🎙] [继续追问..............................] [发送]
附带信息：当前题目 ✓  我的答案 ✓  学习画像 □
```

- 原始解析和 AI 区域必须使用不同背景、边框与“AI 辅助”标签；
- 默认上下文包括 `question_id`、题干、选项、用户答案、正确答案、考点、来源和原始解析；
- 不默认附带其他题目或完整学习记录；
- 对话按 `question_id` 隔离，切题不能串用上一题上下文；
- 原始解析缺失时必须明确标注，问泽生成内容不能冒充题库解析；
- 问泽服务故障不影响查看原始解析、下一题或退出练习。

### 20.7 语音输入规范

首页问泽和逐题问泽都支持麦克风输入：

1. 浏览器使用 `MediaRecorder` 获取短音频；
2. 首次使用前解释用途并请求麦克风权限；
3. 状态完整覆盖：待授权、录音中、已暂停、处理中、已转写、失败、取消；
4. 录音中显示时长、停止和取消；取消后不得上传；
5. 停止后由用户确认再提交转写；
6. 转写结果先进入文字输入框，允许修改；用户再次点击发送后才进入问泽；
7. 默认不持久保存原始录音；
8. 浏览器不支持、权限拒绝、离线、超时或识别失败时无损回退到文字输入；
9. 拒绝权限后不得循环弹窗；
10. 前端不得保存 AI 或语音服务密钥。

接口增补：

```ts
interface SpeechInputService {
  getStatus(): Promise<{ available: boolean; formats: string[] }>;
  transcribe(input: {
    audio: Blob;
    language: "zh-CN";
  }): Promise<{ text: string }>;
}
```

建议占位 HTTP 边界：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/speech/v1/status` | 查询语音输入能力和支持格式 |
| POST | `/api/speech/v1/transcriptions` | 将用户确认上传的短录音转为文字 |
